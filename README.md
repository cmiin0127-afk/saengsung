# 진로핏 (Jinrofit)

희망하는 직업과 해당 직업에서 수행할 것으로 예상하는 업무·필요 역량을 입력하면, 2025년 신직업 연구에 수록된 직업정보와 비교해 볼 수 있는 모바일형 웹 프로토타입입니다.

## 주요 기능

- **2단계 직업 비교 입력**
  1. 희망 직업명 입력
  2. 예상 주요 업무와 필요 역량을 한 화면에서 입력
- **직업 비교하기**: 홈의 버튼을 누르면 직업 세세분류 537개 목록이 선택 창으로 열리고, 직업명을 검색해 선택할 수 있습니다.
- **신직업 별도 창**: 홈의 '요즘 떠오르는 신직업' 메뉴에서 2025년 연구 최종 선정 신직업 41개와 직무개요를 새 창으로 탐색할 수 있습니다.
- **신직업 자동완성**: 연구 데이터에 포함된 신직업을 직업명, 직군, 영역 기준으로 검색하고 선택할 수 있습니다.
- **직업 추천**: 등록된 신직업 중 하나를 무작위로 추천합니다.
- **직업정보 비교**: 신직업 41개는 보고서의 직무개요와 입력 내용의 겹치는 키워드를 비교합니다. 일반 직업은 첫 번째 파일에 포함된 분류 코드를 표시합니다. 첫 번째 파일에는 업무·역량 설명이 없으므로 일반 직업의 키워드 비교는 제공하지 않습니다.
- **비교 결과 안내**: 주요 업무, 필요 역량, 직업 분류를 나누어 확인하고 관련 직업 및 추가 탐색 질문을 제공합니다.
- **마이페이지**: 비교 기록과 좋아요한 직업을 확인할 수 있습니다.
- **반응형 모바일 UI**: 모바일 화면을 중심으로 구성된 인터페이스를 제공합니다.

## 실행 방법

별도의 패키지 설치나 빌드 과정은 필요하지 않습니다.

### 방법 1. VS Code Live Server 사용 (권장)

1. 압축을 해제합니다.
2. 프로젝트 폴더 `JinroFit`을 Visual Studio Code에서 엽니다.
3. Live Server 확장 프로그램을 설치합니다.
4. `index.html`을 열고 **Go Live**를 실행합니다.
5. 브라우저에서 열린 페이지를 이용합니다.

### 방법 2. Python 간이 웹 서버 사용

프로젝트 루트 디렉터리(`index.html`이 있는 위치)에서 터미널을 열고 다음 명령을 실행합니다.

```bash
python -m http.server 8000
```

브라우저에서 아래 주소로 접속합니다.

```text
http://localhost:8000
```

> JSON 파일을 `fetch()`로 불러오므로 `index.html`을 파일 탐색기에서 직접 여는 것보다 로컬 웹 서버를 통해 실행하는 것을 권장합니다. `file://` 환경에서는 JSON 요청이 차단될 수 있으며, 이 경우 프로젝트에 포함된 `data/data-fallback.js`를 대체 데이터로 사용하도록 구현되어 있습니다.

## 프로젝트 구조

```text
JinroFit/
├── index.html
├── new-jobs.html
├── css/
│   └── style.css
├── js/
│   └── main.js
├── data/
│   ├── 2025_new_jobs_study_summary.json
│   ├── job_subclassifications.json
│   ├── occupations_537.json
│   └── data-fallback.js
└── README.md
```

| 경로 | 설명 |
| --- | --- |
| `index.html` | 화면 구조, 입력 단계, 결과 화면, 하단 메뉴 및 로그인 모달 |
| `css/style.css` | 화면 레이아웃, 색상, 컴포넌트 및 반응형 스타일 |
| `js/main.js` | 화면 전환, 입력 검증, 직업 목록 창, 직업 비교, 마이페이지 기능 |
| `data/job_subclassifications.json` | 2025 신직업 연구 직업 데이터. 앞의 41개를 최종 선정 신직업 창에서 사용 |
| `data/2025_new_jobs_study_summary.json` | 연구 정보, 영역별 최종 선정 직업 목록, 신직업의 공통 특징 |
| `data/occupations_537.json` | 사용자가 제공한 직업 세세분류 537개 데이터 |
| `new-jobs.html` | 2025 신직업 41개를 별도 창에서 검색·탐색하는 화면 |
| `data/data-fallback.js` | JSON 로딩 실패 시 사용하는 대체 데이터 |

## 데이터 및 비교 방식

직업 데이터는 `data/job_subclassifications.json`에서 불러오며, 연구 요약 정보는 `data/2025_new_jobs_study_summary.json`에 저장되어 있습니다. 요약 데이터에는 총 **41개 신직업**과 영역별 분류, 신직업의 공통 특징이 포함되어 있습니다.

연구 정보에 기재된 출처는 다음과 같습니다.

- 발행기관: 한국고용정보원
- 자료명: 「2025 국내외 직업 비교 분석을 통한 신직업 연구(신성장 산업 2차 연도 연구)」
- 발행일: 2025년 12월
- 저자: 김중진, 이윤선, 김형래, 조아름, 이유진

비교는 사용자가 입력한 업무·역량 문구와 데이터의 직무개요에 포함된 단어를 대조하는 **키워드 기반 방식**입니다. 문맥이나 의미를 이해하는 AI 모델을 호출하는 기능은 아니므로, 결과는 참고용으로 활용해 주세요.

## 데이터 저장 및 로그인 안내

- 비교 기록은 브라우저의 `localStorage`에 최대 30건까지 저장됩니다.
- 좋아요한 직업도 브라우저의 `localStorage`에 저장됩니다.
- 저장 정보는 현재 사용 중인 브라우저 및 기기에 종속되며, 다른 기기와 자동으로 동기화되지 않습니다.
- Firebase Authentication 이메일·비밀번호 회원가입/로그인 코드는 포함되어 있습니다. 다만 실제 사용을 위해서는 Firebase 프로젝트 설정값 입력과 Email/Password 인증 활성화가 필요합니다.
- 비교 기록과 좋아요는 브라우저 localStorage에 저장되며 서버 DB와 기기 간 동기화는 구현되어 있지 않습니다.

## PRD 관리

PRD(Product Requirements Document)는 진로핏의 목적, 사용자 요구사항, 기능 범위, 데이터·비교 기준, 테스트 및 완료 조건을 관리하는 기준 문서입니다.

| 항목 | 내용 |
| --- | --- |
| 현재 프로젝트 버전 | **0.4** |
| 기준 PRD 버전 | **PRD ver0.4** |
| PRD 파일 | `11.pdf` (전달된 PRD 문서) |
| 버전 기준 | 현재 전달된 압축파일을 프로젝트 버전 0.4로 관리하며, PRD ver0.4를 해당 버전의 요구사항 기준으로 사용합니다. |

### 버전 관리 원칙

- 프로젝트 기능이나 요구사항이 변경되면 PRD 버전을 함께 갱신합니다.
- 변경 이력에는 프로젝트 버전, 변경 일자, 이전 버전 대비 주요 변경 내용을 기록합니다.
- PRD에 명시된 요구사항과 실제 구현된 기능을 구분하며, 문서에 기재되어 있다는 이유만으로 구현 완료로 간주하지 않습니다.
- 날짜가 확인되지 않은 과거 변경 사항은 임의로 추정하지 않고 `미기재`로 표시합니다.
- 다음 버전부터는 PRD 버전과 프로젝트 버전을 함께 기록하고, 변경된 요구사항 및 구현 여부를 확인합니다.

## 참고

이 프로젝트는 브라우저에서 실행하는 프론트엔드 프로토타입입니다. 실제 서비스로 운영하려면 사용자 인증, 서버 저장소, 데이터 관리 및 비교 로직 고도화 등이 추가로 필요합니다.


## 이번 수정 사항 및 Firebase 설정 (회원 기능 활성화)

- 마이페이지 비교 기록에 개별 삭제 버튼을 추가했습니다.
- 비교 기록에 식별 ID를 생성하여 특정 기록을 삭제할 수 있습니다.
- 회원가입/로그인 UI를 Firebase Authentication 이메일·비밀번호 인증 방식으로 연결할 수 있도록 구성했습니다.
- Firebase가 활성화된 상태에서는 비교 기록과 좋아요 저장 키를 사용자 UID별로 구분합니다. (현재 저장 방식은 브라우저 localStorage이며, 다른 기기 간 동기화/서버 저장은 포함하지 않습니다.)
- 기존 직업 비교는 `data/job_subclassifications.json`의 `직무개요` 값을 실제 업무 비교에 사용합니다. 해당 JSON에는 별도의 역량 필드가 없어서 필요 역량 비교 역시 직무개요 텍스트를 대상으로 키워드를 비교하는 한계가 있습니다.

### Firebase 설정 절차
1. Firebase Console에서 프로젝트를 생성합니다.
2. Authentication > Sign-in method에서 Email/Password를 활성화합니다.
3. Firebase 프로젝트 설정에서 웹 앱을 등록하고 설정값을 확인합니다.
4. `index.html`의 `firebaseConfig` 항목 (`YOUR_API_KEY` 등)을 실제 프로젝트 값으로 바꿉니다.
5. 파일을 `file://`로 직접 열지 말고 VS Code Live Server 또는 GitHub Pages 등 웹 서버로 실행합니다.

**보안/기능 범위:** Firebase 인증은 활성화할 수 있도록 코드에 연결했지만, 프로젝트 설정값을 사용자 측에서 입력해야 실제 계정 기능이 작동합니다. 비교 기록/좋아요는 브라우저 로컬 저장 방식이므로 UID별 구분은 같은 브라우저 내에서의 구분이며, 서버 DB와 보안 규칙에 기반한 데이터 보호 및 기기 간 동기화는 별도 Firebase Firestore 구축이 필요합니다.


## 사용 시 주의

- 비교 결과는 키워드 기반 비교이며, 문맥이나 의미를 이해하는 AI 분석 결과가 아닙니다. 결과를 참고 자료로 활용하고 실제 직무정보를 추가로 확인하세요.
- 입력창에는 기본 답변을 채워두지 않고 placeholder 예시만 표시하도록 구성했습니다.
